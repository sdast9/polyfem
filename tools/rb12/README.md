# RB-12 repeatability, provenance and release checks: tools

Runner behind [docs/rb-12-validation.md](../../docs/rb-12-validation.md).
The run identity itself (stage 1) is in the solver: every `PolyFEM_bin` run
writes `run-manifest.json` (schema `polyfem.run-manifest`, see
[scenes/semi-implicit/README.md](../../scenes/semi-implicit/README.md#run-manifest-rb-12)
and `src/polyfem/io/RunManifest.hpp`); the build identity it embeds is
generated by `cmake/polyfem/polyfem_generate_build_info.cmake` before every
build of the library.

## `repeat.py` — controlled repeatability (stage 2)

```sh
python3 tools/rb12/repeat.py --binary build/PolyFEM_bin --output /absolute/fresh/dir \
    [--fixtures quasistatic-semi quasistatic-semi-friction quasistatic-semi@dt=0.0625] \
    [--threads default 1] [--repeats 5] [--timeout 3600] [--roundoff 1e-12] [--verify]
```

Each fixture (a public scene of `scenes/semi-implicit`, with an optional
`@dt=` override — `quasistatic-semi@dt=0.0625` is the PF-08 fine-load case
that failed once and passed on its repeat) is run `--repeats` times per thread
setting from its own isolated input directory (scene and meshes copied,
`output/json` and `output/physical_diagnostics` enabled). Per run the
`result.json` keeps the exit status, wall time, the manifest's identity
(executable and effective-input hashes, thread count, source commits and
patch hashes, peak RSS), the step history (subsolve iterations and
termination reasons, restarts, stall retunes, lagging state, trim, refresh
id, batch median, fallback / continuation counts, broad-phase candidate
counts), the RB-04 endpoint scalars (elastic / barrier / kinetic energy,
free residual, min det F, support and external work increments, frictional
dissipation, the summed support reaction, `physical_balance_pass`) and the
last saved solution (`last_solution.npy`).

Comparison rule (declared in the record): two repeats with an identical step
history must agree on the last solution to `--roundoff` (`‖du‖∞`, internal
length; default 1e-12) and on every endpoint scalar to the same relative
amount — anything larger is a *violation*. Repeats whose histories differ
(a different iteration count, termination reason, restart or trim decision)
are a *branch divergence*: reported with the first differing step and the
endpoint difference, never averaged away. The serial-versus-threaded table
compares every completed pair across thread settings the same way.
`--verify` exits 1 on any violation or any run that did not complete.
`summary.json` / `summary.md` hold the matrix; every run directory is kept.
